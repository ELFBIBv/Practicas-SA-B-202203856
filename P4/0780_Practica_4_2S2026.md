## 3. Enunciado de la Práctica

### 3.1 Descripción del problema a resolver

El estudiante deberá diseñar e implementar un sistema basado en **arquitectura de
microservicios con temática libre**. El objetivo es simular un entorno empresarial moderno
basado en contenedores y arquitectura distribuida.

El sistema deberá cumplir con los siguientes requerimientos:

```
● Estar compuesto por mínimo 4 microservicios funcionales.
● Integrar el servicio de autenticación desarrollado en la Práctica 2.
● Cada microservicio debe tener al menos un endpoint funcional.
● Implementar Docker para cada servicio mediante un Dockerfile individual.
● Implementar un API Gateway funcional que consuma todos los microservicios.
● Utilizar al menos 2 lenguajes de programación distintos entre los microservicios.
● Implementar Docker Compose para levantar todo el sistema con un solo comando.
```
### 3.2 Alcance de la práctica

**Obligatorio:**

```
● 4 microservicios mínimo, cada uno con al menos 1 endpoint funcional.
● Dockerfile individual por cada microservicio.
● Archivo docker-compose.yml funcional que levante todo el sistema.
● API Gateway funcional que enrute hacia todos los microservicios.
● Uso de al menos 2 lenguajes de programación distintos.
● GraphQL implementado en al menos 2 servicios.
● Diagrama de arquitectura (comunicación entre servicios).
● Diagrama de despliegue.
```

Práctica - Vigente para el Segundo Semestre 2026

```
● Diagrama ER completo de las bases de datos.
● Documentación técnica completa.
● Repositorio en la nube con la estructura solicitada.
● Contrato de microservicios en Swagger o Postman.
```
**No requerido (pero recomendado):**

```
● Comunicación directa entre microservicios (sin pasar por el Gateway).
● Implementación de base de datos separada por servicio.
```

● API: GraphQL implementado en al menos 2 servicios.
